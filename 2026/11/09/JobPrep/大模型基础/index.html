# Token

# 什么是 Token？

模型无法直接处理自然语言，只能处理数字。Tokenizer 把文本切成一个个片段，每个片段对应词表中的一个整数编号，这个片段就是 token，编号就是 token id。

注意区分两个概念：

  • token：文本片段，例如 low 、 new 、一个汉字、一个标点；
  • token id：该片段在词表中的整数编号，例如 low → 3721 。

token id 之后才会通过词嵌入变成向量（下一节）。token 是模型理解与计量文本的基本单位：上下文窗口大小、API 计费、训练数据规模，都是按 token 数量计算的。

# Tokenizer：Token 是怎么产生的？

产生 token 的过程分为两大阶段：

  1. 词表构建阶段：训练 tokenizer（分词器），确定词表；
  2. 推理分词阶段：调用 encode ，用已固定的词表切分新文本。

主流分词算法及代表模型：

分词算法代表模型特点
BPE / BBPEGPT、LLaMA、Qwen 等按高频相邻单元逐步合并；字节级 BPE 无 OOV
WordPieceBERT按似然选择合并，词表带 ## 前缀子词
UnigramT5（SentencePiece）从大词表逐步删减，按概率选择最优切分

其中 BBPE（Byte-level BPE） 是 GPT、LLaMA 等 Decoder-only 模型广泛使用的分词算法，分为 ** 分词器训练（构建词表）与推理分词（切分新文本）** 两个阶段。

# 阶段一：训练分词器，构建静态词表

该阶段在模型预训练前一次性完成，词表训练完成后固定不变。

  1. 初始化基础单元：将所有文本转为 UTF-8 字节流，初始单元为 0~255 共 256 个字节，构成初始词表。天然保证无未知字符（无 OOV）。示例初始单元： l, o, w, n, e, i, d 。
  2. 语料预处理：把海量训练文本全部转换成连续的字节序列。示例语料： low low low new new wide wide ，展开为基础单元序列： l o w, l o w, l o w, n e w, n e w, w i d e, w i d e 。
  3. 统计相邻单元对频次：遍历字节序列，统计所有相邻单元对共同出现的次数。统计结果： l o :3、 o w :3、 n e :2、 e w :2、 w i :2、 i d :2、 d e :2。
  4. 合并最高频对子：选取频次最高的相邻单元对，合并为一个新子串，作为新 token 加入词表。最高频对 l o 合并为新 token lo 。序列更新为： lo w, lo w, lo w, n e w, n e w, w i d e, w i d e 。
  5. 循环迭代：使用合并后的新序列，重复「统计频次 → 合并最高频对子」流程。
    • 新一轮统计最高频 lo w → 合并为 low ，序列更新为： low, low, low, n e w, n e w, w i d e, w i d e ；
    • 继续循环，依次合并 n e → ne 、 ne w → new 、 w i → wi 、 wi d → wid 、 wid e → wide 。
    • 频次相同时任选其一即可，实际实现按固定规则选择，保证训练结果可复现。
  6. 终止条件：当词表总规模达到预设目标（如 32000、128000），停止训练，词表定型。

最终词表包含四类内容：原始 256 个基础字节、高频短片段、高频完整词 / 汉字片段、标点符号。

核心特点：合并仅依据共现频次，不理解语义。

# 阶段二：推理阶段，使用已有词表切分文本

输入未见过的新文本，使用已经固定的词表执行贪心最长匹配：

  1. 文本转为字节序列；
  2. 从当前位置开始，优先匹配词表里最长的合法子串，切分为一个 token；
  3. 剩余序列继续向后匹配；
  4. 若长片段无法匹配，持续向下拆分，直至拆到基础字节单元。

示例一：词表包含 low 、 new 、 wide 、 lo 、 w 、 l 、 o 、 n 、 e 、 i 、 d 。输入 low new ：

  • 开头优先匹配最长： low 命中，切出 token low ；
  • 剩余 new ，最长匹配命中，切出 token new ；
  • 结果： low + new 。

示例二：词表有 token 、 izer ，没有 tokenizer 。输入 tokenizer ：

  • 最长匹配得到 token ，剩下 izer ；
  • 剩下部分匹配得到 izer ；
  • 结果： token + izer 。

示例三：某个罕见汉字训练语料中出现极少，词表没有对应的合并片段。UTF-8 下该汉字占 3 个字节，分词器无法匹配更长组合，最终拆成 3 个基础字节 token。

准确补充：真实 BPE 推理并不完全等同于「贪心最长匹配」，而是按训练得到的合并规则优先级（rank）从小到大依次应用。贪心最长匹配是便于理解的简化模型，多数示例下结果一致，但遇到多个候选 token 重叠时可能不同。

# 链路串联

# 关键要点

  1. token 是分词器训练阶段生成的，大模型预训练、SFT 过程不会新增 token（除非专门扩充词表）；
  2. 词表与模型绑定，推理必须使用配套的 tokenizer；换 tokenizer 等于换了一套输入编码；
  3. 中文单个汉字占 3 个 UTF-8 字节，高频字通常能合并成 1 个 token，高频不足时可能被切成 2~3 个 token；
  4. 特殊 token（如 <|endoftext|> 、 <s> 、 <|im_start|> ）也占编号，由对话模板和系统使用，不是普通文本切出来的。

# 实用补充：Token 数量与上下文窗口

不同 tokenizer 的切分结果不同，以下是粗略经验值：

  • 英文：约 4 个字符 ≈ 1 个 token；
  • 中文：常见字约 1 个字 ≈ 1 个 token，生僻字或表情可能占 2~4 个 token；
  • 代码：取决于缩进、符号密度和常见标识符；
  • API 计费通常同时统计输入和输出 token；
  • 上下文窗口指模型一次能处理的最大 token 数（输入 + 生成），超出后需要截断、摘要或改用 RAG。

# 词嵌入（Embedding）

# 为什么不能直接用 token id？

token id 只是编号，数字大小没有语义：id 3093 和 3094 不代表两个词更相似。直接把 id 当成一个数值输入神经网络，会引入错误的数值关系。

两个替代方案：

  • One-hot 编码：维度等于词表大小（十万级），极其稀疏；任意两个词的相似度都是 0，无法表达语义相似性；
  • 词嵌入：把每个 token 映射为一个低维稠密向量（如 4096 维），向量本身可学习，语义相近的词向量会靠近。可以把它看作对 one-hot 做一次可学习的降维。

# Embedding 的本质：一张可学习的查找表

Embedding 层就是一个矩阵 EEE，形状为 [vocab_size, d_model] 。输入 token id，取出对应的一行：

xt=E[token_idt]x_t = E[\text{token\_id}_t]xt​=E[token_idt​]

  • 词表 10 万、 d_model = 4096 时，仅 embedding 层就有约 4 亿参数；
  • 这个矩阵不是人工设计的，而是随机初始化后随模型训练通过梯度下降更新；
  • 训练后可以用余弦相似度衡量两个词向量的接近程度：

cos⁡(a,b)=a⋅b∥a∥∥b∥\cos(a, b) = \frac{a \cdot b}{\lVert a \rVert \lVert b \rVert}cos(a,b)=∥a∥∥b∥a⋅b​

例如模型在大量语料中见过「猫 喜欢 吃 鱼」「狗 喜欢 吃 肉」，那么「猫」和「狗」的向量会靠近；而「猫」和「汽车」会远离。向量之间的距离反映的是用法上的相似性。

# 位置信息：Transformer 本身没有顺序感

自注意力对输入是位置无关的：把词序打乱，注意力算出的结果不会体现先后。但语言有顺序（「狗咬人」≠「人咬狗」），所以必须额外注入位置信息：

  • 早期 Transformer：正弦位置编码，表示绝对位置；
  • 现代大模型：RoPE（旋转位置编码），把位置信息以旋转的形式作用在 Q、K 上，能更好地表达相对位置；
  • 也有可学习位置嵌入等方案。

# 注意力机制

# 直觉：让每个 token 动态地「看」上下文

同一个词在不同语境下含义不同：「吃苹果」和「苹果发布会」。如果每个 token 只有固定的词向量，模型无法区分。注意力机制让每个 token 根据当前上下文，从其他 token 处收集相关信息，得到上下文相关的表示。

# Q、K、V：一次「带目标的检索」

可以把注意力理解为图书馆查书：

  • Query（查询）：我想找什么信息，由当前 token 发出；
  • Key（键）：每个 token 用什么「标签」供别人匹配；
  • Value（值）：每个 token 真正携带的内容。

计算时，用 Q 和所有 K 做点积，得到相关性分数；softmax 归一化成权重；再用权重对所有 V 加权求和。相关度高的 token，其信息被更多地汇总进来。

# 计算公式

Attention(Q,K,V)=softmax(QK⊤dk)V\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QK⊤​)V

其中：

  • Q∈Rn×dkQ \in \mathbb{R}^{n \times d_k}Q∈Rn×dk​、K∈Rn×dkK \in \mathbb{R}^{n \times d_k}K∈Rn×dk​、V∈Rn×dvV \in \mathbb{R}^{n \times d_v}V∈Rn×dv​，nnn 为序列长度；
  • QK⊤QK^\topQK⊤ 得到 n×nn \times nn×n 的分数矩阵，第 iii 行第 jjj 列表示第 iii 个 token 对第 jjj 个 token 的关注分数；
  • 除以 dk\sqrt{d_k}dk​​ 是缩放：点积的方差随维度增大而增大，不缩放会让 softmax 进入饱和区、梯度接近 0；
  • softmax 按行归一化，得到总和为 1 的注意力权重；
  • 最后用权重对 V 加权求和。

# 自注意力与多头注意力

  • 自注意力（Self-Attention）：Q、K、V 都来自同一个序列，只是分别经过 WQW_QWQ​、WKW_KWK​、WVW_VWV​ 三个不同的线性投影。
  • 多头注意力（Multi-Head Attention）：把 d_model 拆成 hhh 个头，每个头用独立的投影计算注意力（每头维度 dk=dmodel/hd_k = d_{model} / hdk​=dmodel​/h），最后把 hhh 个输出拼接，再经过 WOW_OWO​ 投影。不同头可以关注不同模式（局部搭配、指代关系、语法结构等），表达更丰富。

# 因果掩码：生成模型不能偷看答案

Decoder-only 模型训练时一次并行处理整句话，但预测第 ttt 个 token 时只能使用前 ttt 个 token 的信息。做法是在分数矩阵上加上因果掩码：未来位置的分数置为 −∞-\infty−∞，softmax 后这些位置的权重就是 0。

# 复杂度

  • 注意力需要计算 n×nn \times nn×n 的分数矩阵，时间与显存复杂度为 O(n2⋅d)O(n^2 \cdot d)O(n2⋅d)，nnn 为上下文长度；
  • 序列变长时注意力开销快速增长，这是长上下文的核心瓶颈；
  • 常见优化：KV Cache（推理时缓存历史的 K/V）、FlashAttention（分块计算，降低显存读写）、GQA/MQA（多个查询头共享 K/V，减少缓存）。

# 关键要点

  1. 注意力的作用是「按相关性从上下文汇总信息」，输出是上下文相关的表示；

# Transformer

# 三种架构

架构代表模型注意力方向适合任务
Encoder-onlyBERT双向理解、分类、信息抽取

当前主流大模型（GPT、Claude、LLaMA、Qwen 等）基本采用 Decoder-only 架构：结构简单、易于扩展，而且「预测下一个 token」这一目标可以统一各种任务。

# Decoder Block 的结构

模型由 N 个相同的 Block 堆叠而成，每个 Block 包含两个子层（现代大模型普遍使用 Pre-Norm）：

各部分作用：

  • 层归一化（LayerNorm / RMSNorm）：稳定训练。Pre-Norm 把归一化放在子层输入处，残差主通路更干净，深层模型更容易训练；LLaMA 系列使用 RMSNorm。
  • 残差连接： x + 子层输出 ，为梯度提供直通路径，缓解深层网络的梯度消失。
  • 前馈网络（FFN）：通常为「升维 → 激活 → 降维」，中间维度约为 d_model 的 4 倍（LLaMA 使用 SwiGLU，约 8/3 倍）。注意力负责 token 之间的信息交换，FFN 负责对每个 token 单独做非线性变换，通常被认为承担了主要的知识存储。

# 输出层与文本生成

最后一层的输出经过最终归一化和线性层 lm_head （ d_model → vocab_size ），得到词表上每个 token 的 logits；softmax 后得到下一个 token 的概率分布，再按策略采样：

  • 贪心（greedy）：每次取概率最大的 token，结果确定，但容易重复；
  • 温度 temperature：logits 除以 TTT 后再 softmax。T→0T \to 0T→0 接近贪心，TTT 越大分布越平、输出越随机；
  • Top-p（nucleus）：只从累计概率达到 ppp 的最小 token 集合中采样，兼顾质量与多样性。

生成是自回归的：每次产出一个 token，把它追加到输入，再预测下一个，直到遇到结束符或达到长度上限。

# KV Cache

推理第 ttt 步的注意力需要前 t−1t-1t−1 个 token 的 K、V。如果不缓存，每生成一个 token 都要重新计算整段历史的 K/V，代价随长度平方增长。KV Cache 把历史 K/V 存下来，新 token 只计算自己的 Q，大幅降低推理计算量，代价是额外显存；序列越长、层数越多、头数越多，缓存越大。

# 参数量估算

每层 Block 的参数量约为：

  • 注意力：WQW_QWQ​、WKW_KWK​、WVW_VWV​、WOW_OWO​，共 4d24d^24d2；
  • FFN：约 8d28d^28d2（ d → 4d 、 4d → d 两个矩阵）；
  • 合计约 12d212d^212d2（忽略 bias 与归一化层）。

总参数 ≈ 12×L×d212 \times L \times d^212×L×d2。例如 d=4096d=4096d=4096、L=32L=32L=32：12×32×40962≈6.4B12 \times 32 \times 4096^2 \approx 6.4\text{B}12×32×40962≈6.4B，即通常所说的 7B 级别模型。词嵌入层约占 vocab_size × d ，10 万词表下约 4 亿参数，占比不高。

现代大模型还会使用 MoE（混合专家）：把 FFN 拆成多个「专家」，每个 token 只激活其中少数几个，使总参数量与单次计算量解耦。

# 预训练

# 训练目标：预测下一个 token

预训练是自监督学习：给一段文本，让模型根据前面的 token 预测下一个 token。损失函数是交叉熵：

L=−1T∑t=1Tlog⁡Pθ(xt∣x<t)L = -\frac{1}{T}\sum_{t=1}^{T} \log P_\theta(x_t \mid x_{<t})L=−T1​t=1∑T​logPθ​(xt​∣x<t​)

训练时整句话已知，可以用 teacher forcing 一次并行计算所有位置的预测和损失，不需要真的逐字生成。模型为了降低这个损失，会逐渐学到语法、事实知识、推理模式等。

# 数据

  • 来源：网页（如 Common Crawl）、书籍、代码、论文、百科、问答等；
  • 处理：抽取正文 → 语言识别 → 去重（尤其近重复）→ 质量过滤 → 隐私与安全检查 → 按配比混合；
  • 规模：现代大模型通常使用数万亿 token 的训练数据。数据量与模型参数量的比例是重要设计选择：Chinchilla 给出约 20 token / 参数的算力最优参考，实际中常为了让模型更小、推理更便宜而「过训练」。

# 训练规模与并行

预训练需要大规模 GPU 集群，常见并行策略：

  • 数据并行：每个 GPU 处理不同数据批次，同步梯度；
  • 张量并行：把单层的大矩阵切分到多张 GPU 上；
  • 流水线并行：把不同层放到不同 GPU 上，按微批次流水执行；
  • 此外还有 ZeRO / FSDP 等显存优化和混合精度训练。

# 产出：Base Model

预训练得到的是 base model（基座模型）。它学会了续写和大量知识，但不一定会「回答问题」：输入一个问题，它可能续写出更多问题，而不是给出答案。要让它遵循指令、以对话形式回答，需要后续的 SFT、RLHF 等后训练。

# 流程图

# 关键要点

  1. 预训练目标简单但强大：下一个 token 预测，无需人工标注；
  2. 知识主要在这一阶段注入，数据与算力成本也最高；
  3. base model 不等于对话助手，它只是「会续写的模型」；
  4. 预训练不会更新 tokenizer 词表。

# SFT（监督微调）

# 目的

SFT（Supervised Fine-Tuning）用高质量的「指令 — 回答」数据继续训练 base model，让它学会：

  • 对话的格式与角色（system /user/assistant）；
  • 按指令完成任务（总结、翻译、写代码等）；
  • 符合预期的回答风格。

# 数据格式

典型样本是一条条 (instruction, response) 对，也可以是多轮对话。训练前用 chat template 拼接成一条序列，并加入角色标记与特殊 token：

不同模型的模板不同（ <|im_start|> 、 <s> 、 [INST] 等），训练和推理必须使用同一模板。

# Loss Mask：只学习回答部分

SFT 仍然使用下一个 token 预测损失，但不希望模型学习「生成用户的问题」，所以通常把 prompt 部分的 label 置为 -100 （PyTorch 的 ignore_index ），只对 assistant 回复计算 loss：

# 训练细节

  • 数据量通常几万到上百万条，远小于预训练数据；
  • 学习率较小（如 1e-5 量级），训练 1~3 个 epoch，防止过拟合和灾难性遗忘；
  • 资源有限时可以使用参数高效微调（PEFT），如 LoRA：冻结原模型权重，只训练低秩矩阵，显存需求大幅降低；
  • 数据质量比数量更重要：少量高质量、多样化的指令数据往往效果显著。

# 局限

SFT 主要教「格式、任务模式、风格」，很难注入全新知识或纠正预训练中的事实错误；它也无法表达「两个都不错的回答里，人类更喜欢哪个」。前者需要在预训练数据上下功夫或使用 RAG，后者需要 RLHF / DPO。

# 关键要点

  1. SFT = 用指令数据做监督学习，目标是「听指令、会对话」；
  2. 训练目标仍是下一个 token 预测，但通常只对回答部分计算 loss；
  3. 与预训练相比：数据少而精、学习率小、训练轮数少；
  4. SFT 不能解决幻觉和偏好对齐问题，需要后训练继续处理。

# RLHF（基于人类反馈的强化学习）

# 动机

SFT 教模型「模仿标准答案」，但现实中同一问题有很多合理回答，人类有偏好：更准确、更简洁、更安全。RLHF 用人类偏好作为优化信号，让模型的输出更符合人类期望，通常围绕三个目标：有用（helpful）、诚实（honest）、无害（harmless）。

# 三阶段流程

  1. SFT：先得到能对话的模型（上一节）。
  2. 训练奖励模型（Reward Model）：对同一个 prompt，让模型生成多个回答，由人类（或强模型）排序，得到偏好对 (chosen, rejected) 。训练奖励模型给回答打分，目标是让 chosen 的分数高于 rejected。常用 Bradley-Terry 形式：

LRM=−log⁡σ(r(x,ychosen)−r(x,yrejected))\mathcal{L}_{RM} = -\log \sigma\left(r(x, y_{chosen}) - r(x, y_{rejected})\right)LRM​=−logσ(r(x,ychosen​)−r(x,yrejected​))

  1. PPO 强化学习：策略模型（即要训练的大模型）生成回答，奖励模型打分作为奖励，用 PPO 更新策略，使高分回答的概率上升。同时加入 KL 惩罚，约束新策略不要偏离 SFT 参考模型太远：

目标≈E[r(x,y)]−β⋅KL(πθ∥πref)\text{目标} \approx \mathbb{E}[r(x, y)] - \beta \cdot \mathrm{KL}(\pi_\theta \,\|\, \pi_{ref})目标≈E[r(x,y)]−β⋅KL(πθ​∥πref​)

KL 项用于防止模型为了刷分而钻奖励模型的空子（reward hacking），也避免语言退化。

PPO 阶段通常同时维护四个模型：策略模型、参考模型、奖励模型、价值模型（critic），训练复杂、显存开销大、稳定性要求高。

# DPO：更简单的偏好优化

DPO（Direct Preference Optimization）直接用偏好对优化语言模型，不需要单独训练奖励模型，也不需要在训练中做强化学习采样。它把「奖励建模 + 策略优化」合并成一个类似分类的损失：提高 chosen 回答的相对概率，压低 rejected 回答的相对概率，同样带有参考模型的约束。实践上更简单、更稳定，已成为常见的对齐方案；PPO 类在线方法在探索能力和效果上限上仍有优势。

# 演进（了解即可）

  • RLAIF：用强模型代替人类标注偏好，降低成本；
  • RLVR（可验证奖励）：数学、代码等任务答案可以自动验证，直接用正确性作为奖励信号；
  • GRPO：PPO 的简化版，用组内多次采样的相对得分作为优势，省掉价值模型；
  • 推理模型（o1、DeepSeek-R1 等）：用强化学习激励长链思考与自我检查，是 RL 在后训练中的进一步应用。

# 流程图

# 关键要点

  1. RLHF 优化的是「人类偏好」，不是绝对的事实正确性；标注偏好本身可能有偏差；
  2. 奖励模型是偏好的代理，KL 约束防止策略过度优化代理奖励；
  3. DPO 把 RLHF 简化为离线监督式训练，无需奖励模型和 PPO，工程上更容易落地；
  4. RLHF / DPO 在 SFT 之后进行，通常作为对齐的最后一步。

# 总结

# 三个阶段对比

阶段数据训练目标解决的问题产出
预训练海量无标注文本预测下一个 token语言能力、世界知识Base Model
SFT指令 — 回答对预测下一个 token（只算回答）对话格式、指令遵循Instruct Model
RLHF / DPO回答偏好对奖励 / 偏好最大化有用、诚实、无害对齐模型

# 高频面试问题速记

  1. 为什么用 BPE/BBPE，而不是按词切分？
    按词切分词表会爆炸、存在 OOV、难以处理新词和跨语言符号；BPE 把高频片段合成 token，词表规模可控且压缩率高；字节级 BPE 以 256 个字节为起点，任何文本都能编码，没有 OOV。
  2. 为什么注意力要除以 dk\sqrt{d_k}dk​​？
    点积结果的方差随 dkd_kdk​ 线性增大，不缩放会使 softmax 输出接近 one-hot，梯度极小、训练不稳；除以 dk\sqrt{d_k}dk​​ 把方差控制在 1 附近。
  3. Pre-Norm 和 Post-Norm 的区别？
    Post-Norm 把归一化放在残差相加之后（原始 Transformer），需要 warmup，深层难训；Pre-Norm 放在子层输入处，残差通路干净，训练更稳定，是现代大模型的主流选择。
  4. SFT 和预训练的区别？
    预训练用海量无标注文本，学习预测下一个 token，获得通用语言与知识能力；SFT 用少量高质量指令 — 回答对，仍用下一个 token 预测但只对回答部分算 loss，让模型学会遵循指令与对话格式。
  5. RLHF 中 KL 惩罚的作用？
    约束策略模型不要偏离 SFT 参考模型太远，防止针对奖励模型的 reward hacking，并保持语言质量与输出多样性。
  6. DPO 和 PPO 的区别？
    DPO 不需要奖励模型、不需要在线采样，直接用偏好对做离线优化，简单稳定；PPO 需要奖励模型与价值模型，在线探索、工程复杂，但可能达到更高的效果上限。
  7. SFT 后为什么还有幻觉？怎么缓解？
    训练目标的本质是「生成概率高的下一个 token」，不是「保证事实正确」；模型在没见过或不确定的内容上会编造。缓解手段包括 RAG（检索增强）、工具调用、约束提示词、RLHF / 偏好优化、输出引用与校验等。
