# 指令集架构（第 5 章）

本章承接上一章的 MARIE 模型，深入考察 ** 指令集架构（ISA）** 的设计问题：指令格式如何编码、数据在 CPU 中如何存放（栈式 / 累加器 / 通用寄存器）、算术表达式如何变成指令序列、扩展操作码如何节省空间、指令有哪些类型，以及最重要的 —— 操作数从哪里找（各种寻址模式）。

# 指令集设计要考虑的问题

对指令集进行编码可以有多种方式。指令集的区分维度包括：

设计指令集时需要权衡的考虑因素：

  • 指令长度（Instruction length）：短指令更好 —— 占用内存空间少、取指快；但短指令限制了指令总数。
  • 定长指令（fixed length）：更容易译码，但浪费空间（如 HALT 这类零操作数指令）。定长指令不必然意味着操作数个数固定 —— 可以设计 "整体定长，但操作数字段比特数可变" 的 ISA。
  • 内存组织（Memory organization）影响指令格式：如果内存是 16/32 位字且不可按字节寻址，就很难访问单个字符 —— 因此机器往往设计成按字节寻址。
  • 寻址模式有多种类型（直接、间接、变址…… 见 5.4）；
  • 字节序（Endianness）：多字节的字在按字节寻址的机器上按什么顺序存放？最低有效字节放在最高地址还是最低地址？
  • 寄存器的数量与组织方式：CPU 中应该有多少寄存器？操作数应该如何存放在 CPU 中？

# 栈式机器的指令格式与后缀表示法

  • 栈式机器使用一操作数和零操作数指令；
  • 许多指令隐含地使用栈中的操作数；
  • **PUSH（入栈）** 与 POP（出栈）只涉及栈的顶部元素；
  • 二元指令（如 ADD、MULT）使用栈顶的两个元素。

# 扩展操作码（Expanding Opcodes）

  • 指令长度受 ISA 支持的操作数个数影响；
  • 指令集中并非所有指令都需要相同数量的操作数；
  • 零操作数指令（如 HALT）在定长指令下必然浪费空间；
  • 收回这些空间的办法之一：扩展操作码（expanding opcodes）—— 允许操作码长度变化，从而创造出非常丰富的指令集。

# 5.4 寻址（Addressing）★

  • ** 寻址模式（addressing modes）** 规定操作数的位置；
  • 操作数可以是一个常数、一个寄存器或一个内存位置；
  • 操作数的实际位置称为它的有效地址（effective address）；
  • 某些寻址模式允许动态地（运行时）确定操作数的地址。

# 主要寻址模式

其他变体（不作详细展开）：间接变址寻址（indirect indexed）、基址 / 偏移量寻址（base/offset）、自相对寻址（self-relative）、自动增量 - 减量寻址（auto increment–decrement）。

# 本章总结

  • ISA 按以下方面区分：每条指令的位数、每条指令的操作数个数、操作数位置、操作数的类型与大小。
  • ** 字节序（endianness）** 是另一个重要的体系结构考量（大端 vs 小端）。
  • CPU 存放数据的方式有：堆栈架构、累加器架构、通用寄存器架构。
  • 寻址模式是 ISA 的重要组成：本章考察了立即、直接、间接、寄存器、寄存器间接、变址、基址、堆栈等寻址方式。
