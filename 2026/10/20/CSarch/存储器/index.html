# 存储器（第 6 章）

第 6 章 "存储器（Memory）" 讨论计算机存储体系的组织方式：从 RAM/ROM 的类型与特性出发，建立 "寄存器 — 缓存 — 主存 — 磁盘" 的层次化存储结构；再重点分析高速缓存（cache）的三种映射方式、替换策略、有效访问时间、写策略以及多级缓存。理解这些内容，是分析系统性能的基础。

本章学习目标：

  • 理解为什么需要不同类型的计算机存储器；
  • 掌握层次化存储器结构（hierarchical memory organization）的概念；
  • 理解每一层存储器如何影响系统性能，以及性能如何度量；
  • 掌握缓存（cache memory）、虚拟存储器、存储器分段、分页与地址转换背后的概念。

# 6.1 介绍

  • ** 存储器（memory）** 位于存储程序计算机（stored-program computer）的核心；
  • 前面的章节已经学习了构成存储器的组件，以及各种 ISA 访问存储器的方式；
  • 本章聚焦于存储器的组织（memory organization）—— 清晰地理解这些思想，是分析系统性能所必需的。

# 6.2 存储器类型

# 主存的两种类型：RAM 与 ROM

  • RAM（random access memory，随机访问存储器）：可读可写；
  • ROM（read only memory，只读存储器）：只读，但断电后数据仍然保留。

# RAM 的两种类型：DRAM 与 SRAM

类型构成是否需要刷新特点与用途
DRAM电容需要（每隔几毫秒）简单、便宜，用于主存
SRAM类 D 触发器电路不需要速度很快，用于缓存
ROM—不需要，只需少量电荷保存永久 / 半永久数据，断电不丢失

# 6.3 存储器的层次结构 ★

  • 一般来说，越快的内存越贵（faster memory is more expensive than slower memory）；
  • 为了以最低成本提供最佳性能（best performance at the lowest cost），存储器按 ** 层次化方式（hierarchical fashion，分层模式）** 组织；
  • 小而快的存储单元放在 CPU 内部，较大、较慢的主存通过数据总线访问；
  • 更大、(几乎) 永久性的存储（磁盘、磁带）则离 CPU 更远。

# 存储器金字塔

图 6-1 存储器层次金字塔

  • 我们最关心的是包含 ** 寄存器、缓存、主存和虚拟存储器（virtual memory）** 的存储层次；
  • ** 寄存器（registers）** 是处理器自身可用的存储位置；
  • 虚拟存储器通常用硬盘实现，它把地址空间从 RAM 扩展到硬盘（extends the address space from RAM to the hard drive）；
  • 虚拟存储器提供更大的空间，缓存提供更快的速度（Virtual memory provides more space. Cache memory provides speed.）。

# 访问过程

  • 数据一旦定位，就把该数据及若干相邻数据元素一起取入缓存（fetch into cache memory）—— 这正是局部性原理的体现。

# 性能术语 ★

# 局部性原理（Principle of Locality）★

# 6.4 高速缓存（Cache Memory）★

# 缓存的作用与特点

  • 缓存的目的：把最近使用过或即将使用的数据存放在离 CPU 更近的地方，以加速访问，而不是放在主存中；
  • 缓存比主存小得多，但访问时间只是主存访问时间的一小部分（a fraction）；
  • 主存按地址（address）访问，而缓存通常按内容（content）访问，因此常被称为按内容寻址的存储器（content addressable memory）；
  • 正因如此，单个很大的缓存并不总是可取的 —— 搜索它需要更长时间（takes longer to search）。

# 三种映射方式

# 直接映射缓存（Direct Mapped Cache）

  • 最简单的缓存映射方式；
  • 设缓存有 N 个块，则主存的第 X 块映射到缓存的第 Y = X mod N 块；
  • 例：有 10 个缓存块时，缓存的第 7 块可能存放主存的第 7、17、27、37…… 块。

以 4 个缓存块、8 个主存块为例：

图 6-2 直接映射：主存块按 mod N 映射到缓存块

主存地址被划分为三个字段：

  • ** 偏移量域（offset field）** 唯一标识某个块内的一个地址；
  • ** 块域（block field）** 选择缓存中的一个唯一块；
  • ** 标签域（tag field）** 是剩下的部分，用于判断缓存中的块是否为主存所要的块；
  • 各字段的大小由主存与缓存的特性共同决定。

图 6-3 直接映射的地址字段：Tag、Block、Offset

例 6.1：主存按字节寻址，共 4 个块；缓存有 2 个块，每块 4 字节。

  • 访问主存地址 3_16 = 0011_2：拆分为 tag=0、block=0、offset=11 → 映射到缓存块 0，tag=0（地址 3 位于主存块 0 中）；
  • 访问地址 A_16 = 1010_2：拆分为 tag=1、block=0、offset=10 → 同样映射到缓存块 0，但 tag=1（对应的主存块是块 2）；缓存块 0 中原先 tag=0 的数据必须被替换。

例 6.2：主存按字节寻址，容量 2^14 字节；缓存 16 个块，每块 8 字节。

例 6.3：主存按字寻址，容量 2048 字节，字长 16 位；缓存 32 块，每块 8 字节。

小结：直接映射按 ** 取模（modular fashion）** 方式把主存块映射到缓存块，映射关系取决于：

  • 主存地址的位数（主存中一共有多少个地址）；
  • 缓存中块的个数（决定块域的位数）；
  • 每块中有多少个地址（字节或字，决定偏移量域的位数）。

# 全相联映射缓存（Fully Associative Cache）

  • 直接映射不需要任何搜索（does not require any searching），因此成本较低：每个主存块都有确定的缓存位置，CPU 只需检查块域就知道去哪里找；
  • 全相联走向另一个极端：允许一个主存块放在缓存中的任意位置；
  • 要找到这样的块，唯一的办法是搜索整个缓存（search all of cache）；
  • 地址只划分成两个字段：**Tag（标记域）** 和 Offset（偏移量域）：

  • 这要求整个缓存由 ** 相联存储器（associative memory）** 构成，以便并行搜索；
  • 一次搜索必须把请求的 tag 与缓存中的所有 tag 进行比较，才能确定所需数据块是否存在；
  • 相联存储器需要专门的硬件支持相联搜索，因此相当昂贵；
  • 若所有 tag 都不匹配，则为缓存缺失，需要从主存取回该块。

图 6-5 全相联缓存的并行 tag 比较（a）与简化电路（b）

  • 仍以前面的 14 位地址、16 块、每块 8 字节为例，全相联的地址格式为 Tag 11 位 + Offset 3 位；
  • 搜索时把地址中的 tag 与缓存中所有有效 tag 比较：匹配则命中；不匹配则缺失，并把该块从主存传送过来。

# 淘汰与牺牲块

  • 直接映射中，只要另一个需要同一缓存块的存储器引用出现，就会 ** 丢弃（evict）** 原块；
  • 全相联没有这种固定映射，因此必须设计算法决定淘汰哪一块；
  • 被淘汰的块称为牺牲块 / 淘汰块（victim block）。

# 组相联映射缓存（Set Associative Cache）

  • 组相联结合了直接映射与全相联两种思想；
  • N 路组相联（N-way set associative）：与直接映射类似，一个存储器引用映射到缓存中的某个特定位置（一个组，set），其中 N 表示组内的块数；
  • 与直接映射不同的是，一个存储器引用映射到一组若干块，这一点又像全相联；

# 组相联的折中地位

  • 组相联是直接映射与全相联之间的良好折中（good compromise）；
  • 研究表明：2 路到 16 路组相联的性能几乎与全相联一样好，而成本只是其一小部分（at a fraction of the cost）；
  • 因此大多数现代计算机系统采用某种形式的组相联，其中 4 路组相联 最常见。

# 替换策略（Replacement Policy）

  • 全相联和组相联中，当需要从缓存中淘汰一个块时，会启用替换策略（replacement policy）；
  • ** 最优替换策略（optimal replacement policy）** 能洞察未来，淘汰最长时间不需要的块；
  • 最优算法无法实现，但它可以作为评估其他方案的基准（benchmark）；
  • 替换策略取决于要优化的局部性，通常关注时间局部性。

  • LRU 与 FIFO 的问题：存在退化引用情形（degenerate referencing situations），可能造成颠簸（thrash）—— 不断把同一块淘汰、取回、再淘汰、再取回。

# 缓存与程序局部性

  • 缓存的有效性依赖程序具有良好的局部性（good locality）；
  • 某些 ** 面向对象程序（object-oriented programs）** 由于复杂、动态的数据结构，局部性较差；
  • 数组按 ** 列优先（column-major）而非行优先（row-major）** 顺序存储时，对某些缓存组织可能造成问题：

图 6-7 行优先（row-major）与列优先（column-major）的访问顺序

  • 局部性差时，缓存反而可能导致性能下降（performance degradation），而不是性能提升。

# 写策略（Cache Write Policies）

  • 缓存替换策略必须考虑脏块（dirty blocks）：在被缓存期间被修改过的块；
  • 脏块必须写回主存；写策略决定如何写回；
  • 两种写策略：写直通（write through）与回写（write back）。

# 数据缓存与指令缓存

  • 前面讨论的缓存称为统一 / 集成缓存（unified/integrated cache）：指令和数据都放在同一个缓存中；
  • 许多系统为数据和指令分别设置缓存 —— 哈佛缓存（Harvard cache）；
  • 大多数程序指令顺序执行，只在过程调用、循环和条件语句时才会分支，因此指令往往具有很高的局部性；
  • 把数据与指令分开可以获得更好的局部性，代价是更大的复杂度。

# 其他缓存优化与多级缓存

  • 受害者缓存（victim cache）：一个小型相联缓存，用来保存最近被淘汰的块；
  • 跟踪缓存（trace cache）：指令缓存的一种变体，保存已译码的分支指令，使非连续（noncontiguous）的指令看起来像连续的一样；

# 本章总结

  • 计算机存储器按层次组织：最小、最快的在顶部，最大、最慢的在底部。
  • 缓存存储器让 CPU 能更快地访问主存中的数据。
  • 最简单的缓存映射方式是直接映射；N 个缓存块时，主存块 X 映射到缓存块 Y = X mod N。
  • 缓存有三种一般类型：直接映射、全相联、组相联。
  • 全相联与组相联需要替换策略：LRU、FIFO、随机；替换策略还必须处理脏块。
  • 写策略包括写直通和写回；现代系统常采用多级缓存（L1、L2、L3）。
