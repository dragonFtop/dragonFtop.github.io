# 计算机模型 MARIE（第 4 章）

本章用一个极简模型机 MARIE（Machine Architecture that is Really Intuitive and Easy，真正直观易学的机器架构）把前几章的知识串起来：从 CPU、总线、时钟、存储器组织讲起，再到指令格式、微操作（RTL）、取指 - 译码 - 执行周期、中断，最后扩展到寻址模式、汇编器、控制单元的两种实现方式，并对照真实的 CISC/RISC 架构。

# 4.1 介绍

  • 第 1 章给出了计算机系统的总览；
  • 第 2 章讨论了数据如何被各类计算机组件存储与操纵；
  • 第 3 章介绍了数字电路的基本元件；
  • 有了这些背景，现在可以理解计算机各组件如何工作、如何组合成有用的计算机系统。

# 4.2 CPU 基础

  • CPU 取指（fetch）、译码（decode）、执行（execute） 程序指令。
  • CPU 的两大部件是数据通路（datapath）与控制单元（control unit）。
  • 数据通路：由算术逻辑单元（ALU）与存储单元（寄存器）通过总线互连而成的网络。


图 4-1 CPU、主存与 I/O 系统的组成

  • 寄存器保存 CPU 能随时快速访问的数据，用 D 触发器（D flip-flop） 实现 —— 一个 32 位寄存器需要 32 个 D 触发器：


图 4-2 D 触发器符号及其状态表

  • ALU 在控制单元指挥下完成逻辑运算（如比较）与算术运算（如加法）。
  • 控制单元依据 ** 程序计数器（PC，程序计数器寄存器）与状态寄存器（status register，状态寄存器）** 中的值决定执行哪些动作。
  • 各部件的操作按控制单元提供的信号有序地进行。

# 4.3 总线

  • CPU 通过 ** 数据总线（data bus）** 与其他系统组件共享数据。
  • 总线（bus）是一组导线，每条线同时传送一个比特。
  • 计算机中常见两类总线：
    • 点对点总线（point-to-point, P2P）：如 ALU 与控制单元之间的专用连线；
    • 多点总线（multipoint bus）：多个部件共享，是共享资源，访问由 ** 内建于硬件的协议（protocols）** 控制。

# 4.4 时钟

  • 每台计算机至少含有一个时钟（clock），用于同步各部件的活动。
  • 每个操作需要固定数量的时钟周期。
  • 时钟频率（MHz、GHz）决定速度；周期时间（cycle time）是时钟频率的倒数：

  • 因此提高性能的三条途径：
    1. 减少程序中的指令数；
    2. 减少每条指令的平均时钟周期数；
    3. 减少每个时钟周期的纳秒数。

# 4.5 输入 / 输出子系统

  • 计算机通过 I/O（输入 / 输出）与外部世界通信，设备通过多种接口连接。
  • I/O 有两种设计方式：
    • 存储器映射（memory-mapped）：I/O 设备被当作主存一样访问 —— 速度快，但占用内存地址空间；
    • 基于指令（instruction-based）：使用专门的 I/O 指令集 —— 不占用内存空间，但要求 CPU 实现这些指令。

# 4.6 存储器组成

  • 存储器是线性排布的可寻址存储单元阵列。
  • 存储单元可以按字节寻址（byte-addressable）或按字寻址（word-addressable，一个 "字" 是两个或更多字节）。
  • RAM 芯片用 "长度 × 宽度" 描述：例如 4M × 16 的 RAM 芯片提供 4M 个 16 位字。
  • CPU 如何访问存储位置：容量 4M 字 = 2^2 × 2^20 = 2^22 个字，编号 0 到 2^22 − 1，因此内存总线至少需要 22 条地址线；地址线以二进制 "计数"，由译码器选中相应单元。
  • 物理内存通常由多块 RAM 芯片组成。把地址 ** 交错（interleave）** 分发到不同芯片可以提高访问效率：
    • 低位交叉（low-order interleaving）：用地址的低位选择芯片；
    • 高位交叉（high-order interleaving）：用地址的高位选择芯片。
  • 例：16 块 2K×8 的芯片组成 32K 字节存储；地址共 15 位 = 4 位选芯片 + 11 位芯片内偏移。

  • 再例：128 字的存储器、8 路低位交叉：

    • 128 = 2^7 → 地址共 7 位，结构为 4 位模块内偏移 + 3 位模块号。

# 4.7 MARIE 模型 ★

MARIE = Machine Architecture that is Really Intuitive and Easy，专为演示计算机系统基本概念而设计。它简单到在现实中做不了什么实际工作，但深入理解它的功能后，你就能理解复杂得多的系统架构。

  • Load 指令在 IR 中的位模式示例： 0001 0000 0000 0100 —— 操作码为 1，要装入数据的地址为 4。

# 微操作与 RTL

  • 每条指令实际上由一系列更小的 ** 微操作（microoperations）** 组成；
  • 微操作序列用 ** 寄存器传输语言（RTL / RTN，寄存器传输语言）** 描述；
  • M[X] 表示内存位置 X 中实际存储的数据值， ← 表示向寄存器或内存传输。

# 4.8 指令的执行 ★

取指 - 译码 - 执行（fetch-decode-execute）周期是计算机运行程序时执行的一系列步骤：

  1. 从内存取出一条指令，放入 IR；
  2. 在 IR 中被译码，确定接下来要做什么；
  3. 如果操作涉及内存中的值（操作数，operand），把它取回并放入 MBR；
  4. 万事俱备，执行指令。

# 4.9 中断

  • 当更高优先级的事件发生时，程序的正常执行会被改变；CPU 通过 ** 中断（interrupt）** 得到通知。
  • 中断可由以下事件触发：I/O 请求、算术错误（如除零）、遇到无效指令。
  • 每个中断都关联一个过程，指导 CPU 在中断发生时该做什么。
  • 中断发生的情形：
    • 用户打断（如 Ctrl+C）；
    • 用户或程序请求 I/O；
    • 发生严重错误。
  • 中断可由硬件或软件产生；软件中断又称为陷阱（traps）。

# 可屏蔽与不可屏蔽中断

  • 通用系统通常在一次中断被处理期间禁用所有中断（通过在标志寄存器中置位实现）；
  • 这种情况下被忽略的中断称为 ** 可屏蔽（maskable，可屏蔽）** 中断；
  • ** 不可屏蔽中断（nonmaskable）** 是那些必须被处理、以保持系统处于稳定状态的中断。

# 中断与 I/O

  • 中断对处理 I/O 非常有用；但中断驱动的 I/O 较复杂，超出本章范围（第 7 章详述）。
  • MARIE 作为最简系统，使用改进形式的程序控制 I/O：
    • 输出放进输出寄存器 OutREG；
    • CPU ** 轮询（polls）** 输入寄存器 InREG，直到检测到输入，此时把该值复制进累加器。

# 4.11 关于汇编程序的讨论

  • 助记指令（mnemonic instruction），如 LOAD 104 ，便于人类编写和理解，但计算机无法理解；
  • 汇编程序（assembler，汇编器）把人类可理解的指令翻译为计算机可理解的机器语言；
  • 在汇编语言中，助记指令与机器码是一一对应的。
  • 汇编器分两轮（two passes）由助记源程序生成目标程序文件（OPF，目标程序文件）：

  • 第一轮：尽可能多地汇编程序，同时建立包含所有符号内存引用的符号表；
  • 第二轮：用符号表中的值补全指令；第二轮结束后汇编完成。

# 4.12 指令集的扩充

  • 到目前为止讨论的所有 MARIE 指令都使用直接寻址模式（direct addressing mode）：操作数的地址显式写在指令中。
  • 还可以使用间接寻址（indirect addressing）：指令中给出的是 **"操作数地址的地址"。用过编程中指针（pointers）** 的人对此不会陌生。

  • 刚才描述的信号模式，无论计算机采用硬连线还是微程序实现，都是相同的；
  • 硬连线控制用指令寄存器（IR）中的位产生控制信号 —— 把这些位送进基本的逻辑门；

  • ** 环形计数器（ring counter）** 产生周期性的时序信号 T0 ~ T4：
    • 初始时除 D0 的输入外，所有触发器输出为低（通过反相或门实现）；

  • 硬连线逻辑可以 "直接画出来"：例如 Add = 0011 指令的控制逻辑由 IR 触发器、与门及 P、A、T、Cr、MR、LALT 各信号线组合而成。
  • 硬连线控制的缺点：逻辑非常复杂；对于指令集很大的计算机，硬连线控制几乎无法实现。

# 微程序控制（Microprogrammed Control）

  • 控制信号由 ** 指令微代码（microcode）** 产生；
  • 所有机器指令被输入一个特殊程序 —— 微程序（microprogram），它把 0 和 1 构成的机器指令 "转换" 成控制信号；
  • 微程序本质上是一个用微代码写的解释器（interpreter），存储在固件（firmware）中，通常称为控制存储器（control store）；
  • 每个时钟周期取出一条微指令（microinstruction），有点像用一个程序计数器从控制存储器中选出下一条指令。

  • 微程序控制单元就像一个微型系统（system-in-miniature）：微指令的取指、译码、执行与常规指令完全一样；
  • 正因为多了一层解释，微程序控制比硬连线控制慢；
  • 优点是：可以支持非常复杂的指令；当指令集变化（或发现错误）时，只需修改微程序即可。

# 4.14 实际的计算机体系结构

  • MARIE 与现代架构共享许多特征，但并不能精确代表它们；本节简要考察两种真实机器架构：Intel 架构（CISC 机器）与 MIPS（RISC 机器）。
  • CISC = complex instruction set computer（复杂指令集计算机）；
  • RISC = reduced instruction set computer（精简指令集计算机）。

# Intel 8086

  • 1979 年诞生的经典 Intel 架构是 CISC 架构；被 IBM 采用于 1981 年发布的著名 PC。
  • 8086 操作 16 位数据字，支持 20 位内存地址（最大可寻址内存 = 2^20 = 1MB）；后来的 8 位版本 8088 为降低成本而推出，同样使用 20 位内存地址。
  • 8086 有 4 个 16 位通用寄存器，可以按半字访问；还有标志寄存器、指令寄存器；通过基址指针（base pointer）和堆栈指针（stack pointer）两个寄存器的值访问堆栈。
  • 8086 没有内置浮点处理；1980 年 Intel 发布 8087 数值协处理器，但因价格昂贵，很少用户选择安装。
  • 1985 年 Intel 推出 32 位 80386（无内置浮点单元）；1989 年的 80486 内置了浮点处理与缓存。
  • 80386 和 80486 都对 8086/8088 向下兼容（downward compatibility）：为小字长系统编写的软件被引导去使用 32 位寄存器的低 16 位。

# MIPS

  • MIPS 家族是同类中最成功的 CPU 家族之一，是最早的 RISC 微处理器之一。
  • 1986 年第一块 MIPS CPU 发布：32 位字长，可寻址 4GB 内存（需 32 位地址）；
  • 多年来 MIPS 处理器既用于通用计算机也用于游戏机；现在提供 32 位和 64 位版本。
  • MIPS 为性能而设计：它是载入 / 存储架构（load/store architecture）—— 只有 load 和 store 指令能访问内存。

# 本章总结

  • 计算机系统的主要组件：控制单元、寄存器、存储器、ALU 和数据总线；内置时钟负责同步。
  • 计算机通过反复的取指 - 译码 - 执行周期运行程序。
  • MARIE 的 ISA 有九条基本指令和六条扩展指令（含间接寻址模式指令 LOADI、STOREI、ADDI、JUMPI）。
  • 控制单元有两种实现方式：微程序控制（microprogrammed control）与硬连线控制（hardwired control）。
  • 不可屏蔽中断必须被处理，以保持系统的稳定状态。
  • Intel 架构是 CISC 架构的例子；MIPS 是 RISC 架构的例子。
